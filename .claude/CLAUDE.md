# litt.md: repo rules

This repo is Nick's design language and taste, packaged as a Claude Code plugin.
The repo root is the plugin root, and the skill lives in `skills/litt-md/`.

## Layout rules

- Never add these at the repo root, because Claude Code auto-loads them as plugin components:
  `commands/`, `agents/`, `hooks/`, `bin/`, `workflows/`, `monitors/`, `themes/`, `output-styles/`, `settings.json`, `.mcp.json`.
  A root `bin/` also makes claude.ai refuse the plugin.
- Keep repo notes in this file (`.claude/CLAUDE.md`). A root `CLAUDE.md` triggers a validate warning.
- `evals/` stays at the root so it never ships inside the claude.ai zip.

## Gallery

`gallery/` is the components gallery: a Vite and React app that Vercel builds from the repo root with `vercel.json`. It is not a plugin component, it does not ship in the claude.ai zip, and there is no root `package.json`, so every gallery command takes `--prefix gallery`.

- Tokens flow one way. `gallery/scripts/sync-tokens.mjs` copies `skills/litt-md/assets/tokens.css` and `tailwind.css` (strict mode on) into the gitignored `gallery/src/styles/`. Never edit the copies. `predev`, `prebuild` and `verify` run the sync.
- Docs data flows one way too. `gallery/scripts/gen-docs.mjs` reads `gallery/src/components` and writes the gitignored `gallery/src/generated/docs.json` (props, defaults, JSDoc, files, packages). `predev`, `prebuild` and `verify` run it after the sync. Document a prop with JSDoc in the component, never in the page.
- The registry flows one way too. `gallery/scripts/gen-registry.mjs` turns the components (and the blocks in `gallery/src/blocks/`, whole screens named after the page that shows them) into the shadcn registry in the gitignored `gallery/public/r/` (served at `https://littmd.vercel.app/r/`), with every litt token renamed `litt-…` so it never collides with a host app. Beside those, each world has its own install (plans/019, shape A): `r/<world>/<part>.json`, named `<world>-<part>`, for every part in the world and every engine, with the contract's `byWorld` map cut by the generator to that world's body (the TypeScript compiler; any other shape of `byWorld` fails the build) and whatever only the other bodies used dropped, and `r/<world>/litt.json` with `:root` and that world's tokens alone. `r/<part>.json` and `r/litt.json` stay as they are. `prebuild` and `verify` run it after the docs data. Never edit the output; fix the source or the generator. `npm run test:registry --prefix gallery` installs every item into fresh Vite and Next.js apps; run it when a component, the motion engine, the tokens or the generator change. Its `worlds` scenario installs every part of every world from `r/<world>/` and fails if an install brings another world's body or tokens.
- Versions flow one way too. `gallery/CHANGELOG.md` (by hand, one release per date) gives every registry item its version; `gen-registry.mjs` stamps it into the item's `meta` and the top of every installed file, and keeps the committed `gallery/registry.lock.json`. An item whose files changed without a newer changelog line fails verify, and a world's item (`device-button`) counts: a change to a part needs a line for each world's copy it changes, and a new part an `added` line in each world it is in. Add the line, run verify, commit the lock with the change. A token change needs a `litt` line (evolve.md, Propagate).
- Agent docs flow one way too. `gallery/scripts/gen-llms.mjs` writes the gitignored `gallery/public/docs/<page>.md`, `llms.txt`, `llms-full.txt` and `changelog.md` from the pages' `meta` and `docs`, `docs.json` and the lock. `predev`, `prebuild` and `verify` run it last.
- The page checks run as a matrix in `.github/workflows/gallery.yml`, at most 19 jobs beside `check` (GitHub's 20). `a11y.mjs` and `reduced-motion.mjs` deal pages by weight (`gallery/scripts/shard.mjs`): each page weighs its seconds in `gallery/scripts/page-costs.json`, pages go longest first to the lightest shard, the same split in every job, and a page the file lacks weighs the median. `npm run test:shards --prefix gallery` (part of `verify`, with its `--self-test`) reads the workflow's `--shard k/n` jobs and fails unless every page lands in exactly one; `--list` prints a shard's pages. When the shards drift, re-measure on a build (`npm run test:a11y --prefix gallery -- --record-costs`, the same for `test:motion`) and commit the file. Before rebalancing a slow job, read its steps: the job caches Playwright's browser and its .debs per runner image, since the Ubuntu mirror can take ten minutes.
- `npm run test:motion --prefix gallery` (CI, after a build) fails if anything moves under reduced motion on any page or overlay; `--self-test` fails if it can no longer see motion with motion allowed.
- `npm run test:reflow --prefix gallery` (CI, after a build) fails if any page scrolls sideways at 320px (WCAG 1.4.10) and names what sticks out; anything inside its own horizontal scroller is fine. `--self-test` puts a 420px block in a page's main and fails if the check misses it.

The hash is the route, so a link keeps the page's address and its click focuses the section's h2 (`tabindex="-1"`, ids from `docs/sections.tsx`) and scrolls it to the top, instantly. Below 640px Props starts closed behind a button with `aria-expanded` (`data-props`), open with a plain title from 640px up; focus on its title opens it, so a jump to Props does. `openVariants` in `routes.mjs` calls `openProps`, so every page check that opens Variants reads Props on a phone too. `npm run test:jump --prefix gallery` (CI, after a build) loads every part's page in every world (each address in `routes()` whose page has `docs`; a block's page has none) at 390 by 844 with touch, and fails unless a link named Install in main sits in the first screen and a tap on it leaves `h2#install` in view with focus on it. - `npm run test:targets --prefix gallery` (CI, after a build) is the only page check that uses a finger: at 390 by 844 with touch, on every page with Variants open, it fails if a visible element with the `litt-target` class computes `position: static`, or if the point at the middle of a touch target in the first screen lands on another one. A touch target grows a control's place for a finger with an absolute `::before` (tokens.css), so the control must be positioned: write `litt-target relative` (or `absolute`), never `litt-target` alone, or its box grows to the nearest positioned ancestor and takes its neighbours' taps, as the player's Index rows and every world's top row did (plans/audits/README.md). `lint:litt` fails the same in the source, so `verify` does (gallery and `--host` mode, rule `other`): a class list (a `cn(...)`, a `className={...}`, a `"a" + "b"` chain or one constant, across lines) with `litt-target` and none of `relative`, `absolute`, `fixed`, `sticky` (bare or `pointer-coarse:`); a list joined with a variable is not judged. `--self-test` unpositions every target and fails if the check misses a page.
