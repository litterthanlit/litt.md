# litt.md: repo rules

This repo is Nick's design language and taste, packaged as a Claude Code plugin.
The repo root is the plugin root, and the skill lives in `skills/litt-md/`.

## Layout rules

- Never add these at the repo root, because Claude Code auto-loads them as plugin components:
  `commands/`, `agents/`, `hooks/`, `bin/`, `workflows/`, `monitors/`, `themes/`, `output-styles/`, `settings.json`, `.mcp.json`.
  A root `bin/` also makes claude.ai refuse the plugin.
- Keep repo notes in this file (`.claude/CLAUDE.md`). A root `CLAUDE.md` triggers a validate warning.
- `evals/` stays at the root so it never ships inside the claude.ai zip.

## Gallery

`gallery/` is the components gallery: a Vite and React app that Vercel builds from the repo root with `vercel.json`. It is not a plugin component, it does not ship in the claude.ai zip, and there is no root `package.json`, so every gallery command takes `--prefix gallery`.

- Tokens flow one way. `gallery/scripts/sync-tokens.mjs` copies `skills/litt-md/assets/tokens.css` and `tailwind.css` (strict mode on) into the gitignored `gallery/src/styles/`. Never edit the copies. `predev`, `prebuild` and `verify` run the sync.
- Docs data flows one way too. `gallery/scripts/gen-docs.mjs` reads `gallery/src/components` and writes the gitignored `gallery/src/generated/docs.json` (props, defaults, JSDoc, files, packages). `predev`, `prebuild` and `verify` run it after the sync. Document a prop with JSDoc in the component, never in the page.
- The registry flows one way too. `gallery/scripts/gen-registry.mjs` turns the components (and the blocks in `gallery/src/blocks/`, whole screens named after the page that shows them) into the shadcn registry in the gitignored `gallery/public/r/` (served at `https://littmd.vercel.app/r/`), with every litt token renamed `litt-…` so it never collides with a host app. `prebuild` and `verify` run it after the docs data. Never edit the output; fix the source or the generator. `npm run test:registry --prefix gallery` installs every item into fresh Vite and Next.js apps; run it when a component, the motion engine, the tokens or the generator change.
- Versions flow one way too. `gallery/CHANGELOG.md` (by hand, one release per date) gives every registry item its version; `gen-registry.mjs` stamps it into the item's `meta` and the top of every installed file, and keeps the committed `gallery/registry.lock.json`. An item whose files changed without a newer changelog line fails verify. Add the line, run verify, commit the lock with the change. A token change needs a `litt` line (evolve.md, Propagate).
- Agent docs flow one way too. `gallery/scripts/gen-llms.mjs` writes the gitignored `gallery/public/docs/<page>.md`, `llms.txt`, `llms-full.txt` and `changelog.md` from the pages' `meta` and `docs`, `docs.json` and the lock. `predev`, `prebuild` and `verify` run it last.
- `npm run test:motion --prefix gallery` (CI, after a build) fails if anything moves under reduced motion on any page or overlay; `--self-test` fails if it can no longer see motion with motion allowed.
- `npm run test:reflow --prefix gallery` (CI, after a build) fails if any page scrolls sideways at 320px (WCAG 1.4.10) and names what sticks out; anything inside its own horizontal scroller is fine. `--self-test` puts a 420px block in a page's main and fails if the check misses it.
- `npm run test:text-zoom --prefix gallery` (CI, after a build) fails if any visible text in a page's main has a line height under 0.95 times its size at 200% text (WCAG 1.4.4), the overlap a px leading makes. `--self-test` puts back the old 22px body leading and fails if the check misses it.
- `npm run test:forced-colors --prefix gallery` (CI, after a build) fails if, under forced colors in light or dark, the row a keyboard is on (menu, select, combobox, command menu, context menu), the selected underline tab or the current code cell looks like its neighbour in a screenshot. `--self-test` puts the old highlights back with injected CSS and fails if the check misses any.
- `npm run test:focus --prefix gallery` (CI, after a build) fails if focus falls to the body after Enter on an overview tile (it lands on the new page's h1), on Sign in's submit while it is busy, or on Slide to confirm by the thumb or by typing, or if `#button` or `#table` shifts more than 0.1 in its first 5s on a slow phone. `--self-test` breaks each scenario in the page and fails if the check misses one.
- `npm run test:corners --prefix gallery` (CI, after a build) fails if, at any shape in `SHAPES` (rules.ts) but Square, written on `<body>` as Customize once did, a box drawn inside a rounded box comes closer to its curve than to the nearest straight side, or a layer (filling three quarters of the box one way and within its radius of an edge: rows in a group, a card's cover) is rounder than the box that holds it, or an inner corner that starts inside the outer one's curve is not the outer radius less the inset within 1px (foundations.md, Concentric). Circles and pills (avatars, icon-only buttons) are round by their size. It reads every page's main at rest, then with every slider at its start and its end (judging only the slider's own parts). Breaks not yet fixed sit in its `KNOWN` list, which prints them and fails when one stops happening. `--self-test` puts the Slider's old cap on a pill, a 22px row in a 16px group and a square cover 4px into a 16px card in a page and fails if the check misses any.
- `npm run test:playground --prefix gallery` (CI, after a build) fails if the Playground's old addresses (`#playground/device`, `#playground`) do not open the players, or if, on any of the six worlds' players (`#<world>`) at 1440 by 1000, the screen does not wear the world or `<html>` changes, the object is not the world's own body (for a world in `OBJECTS`) or `bare` (for one not), Tab from Source does not reach the selector, then Play, then the screen, the arrows, Page Up, End and Home do not move the take with the readout following, a take (every component in the world) draws nothing on the screen, anything in the body is filled with the accent, Menu does not open on the screen or go where you pick, what the Dialog, Menu, Popover, Select, Context menu, Toast or Tooltip take opens leaves the screen or its world, the take moves within 6s with no hand on it, or Play does not move it and a press on the screen stop it. `--self-test` takes the screen's containment away before the Dialog take's dialog opens and keeps the recorder's body from loading, and fails if the check misses either.
- `npm run test:gaps --prefix gallery` (CI, after a build) fails if a pointer between two stacked rows of a clickable list (a nav, a menu, li > a or button, options) lands on neither row, the dead space that makes a hover flicker (foundations.md, section 6). `--self-test` puts two buttons 8px apart in a page and fails if the check misses them. `test:home` also fails if switching the theme starts a transition anywhere in the page but the deck (foundations.md, Motion: a theme switch is instant).
- The overview is a wall of every component as a live tile: a page's `tile` (`<Page tile={…}>`, one object at real size) or its first demo. A tile's expand button, or a click on its empty ground, opens its mosaic (`gallery/src/gallery/mosaic.tsx`): every `Stage` on its page, live (`PreviewContext` "mosaic" in `kit.tsx`), dealt out from the tile on the expressive spring and gathered back when it closes, with the page behind in soft focus (R4). The choreography is `deal`/`gather` in `gallery/src/motion/deal.ts` (it ships in the `motion` registry item). Pages arrive the same way (`gallery/src/gallery/arrival.tsx`): a tile's name deals its page out of the tile, the mosaic's Open page grows each stage out of its piece, any other link nudges the page in from the link's side; only what is on screen moves, and nothing moves on a first load or Back. Elements that arrive carry `data-arrive` ("stage" or "head"). `npm run test:wall --prefix gallery` (CI, after a build) fails on more than one accent fill across the wall, a tile or page that scrolls sideways, or an empty tile.
- Each world is a system with a page of its own, `#<world>/about` (`gallery/src/gallery/world.tsx`, after design.how's systems): the name and its line, the system's scenes (`gallery/src/gallery/systems/<world>.tsx`, contract in `scene.ts`: small live product pieces, no accent fill, the first one the hero), its foundations, Only here and Install, with an On this page rail and a Copy prompt on the right. `#systems` (`pages/00-systems.tsx`, litt.design/systems/, the Home every world links to) lists every world with each system's cover scene as its card, each opening its player. `test:worlds` checks the pages.
- `#canvas` is the language canvas (`gallery/src/canvas/`, after the create-canvas skill): a freeform workspace of live previews for rethinking litt, not a page. It has no nav entry or wall tile, and the page checks never see it. Content lives in `registry.tsx` (ids, names, sizes, positions); experiments stay in the folder and use only tokens, and nothing in `src/components` changes for them; `canvas.tsx` is only the camera, the gestures and the saved layout (camera and positions, under `litt-gallery:canvas:language`). Candidate values under comparison (such as accents) carry `litt-allow` and move into `tokens.css` once picked.
- Each world is closed (plans/019). A world is its pages at `#<world>` and under it, drawn by `gallery/src/gallery/world-site.tsx` with no gallery header or sidebar, and nothing in it links to another world; the only way out is Home, https://www.litt.design/systems/. `#<world>` is the world's player (plans/018, `gallery/src/gallery/play-object/`): its screen opens on Home (the world's line, its core set and an index of every component on its shelf, after design.how's systems) and runs every component in the world (`takes.ts`: the takes on shelves, the page groups in `PAGE_GROUPS` order, and each world's `CORE` set) one take at a time, each drawn as its wall tile (`PreviewContext` "tile"); Left and Right step within a group, Up and Down move a group, and Play runs the core set. One contract (`contract.tsx`: Home, the takes, the selector slider and its two-level keys, Play, Menu (back to Home), Details and Source, the live region, the state) and a body per world that only draws (`bodies/<world>.tsx`, loaded on demand; Device's is the recorder, and a world with none, or whose body fails to load, draws `bodies/bare.tsx`). The screen (`screen.tsx`) wears the world and is the `OverlayRoot` for what a take opens; it is rendered once into a host each body's slot adopts. Play steps a take every 4s only after it is pressed, and any hand stops it; nothing plays on load and nothing makes a sound (plan 018, Decisions 1 and 2). `#<world>/<component>` is that component's page in the world, and `#<world>/about` the world's system page (`world.tsx`). The old addresses redirect (`canonical` in `route.ts`): `#button` to `#flat/button`, `#playground/device` to `#device`. A page in a world shows that world only: no demo or study section lays the worlds side by side (the Systems index alone does). A new body joins `OBJECTS` in `gallery/scripts/playground.mjs`; `test:playground -- --greyscale <dir>` writes the sheet for the test of an object. Every page runs the locked motion; the Tune panel (`motion-panel.tsx`) is out of the UI until a later plan brings it back inside a world.
- Nothing is customized (plans/019): there is no Customize panel, deck or look link in the UI. `customize-state.tsx` keeps only the theme as a choice (light, dark, system); the look is the address's world (`worldOfHash` in `look.ts`), in its own accent, face, shape and Calm, and every page outside a world is the gallery's, Flat. `index.html` paints the first frame from a hand copy of `worldOfHash`, which `npm run test:look --prefix gallery` (part of `verify`) runs against it for every saved look, link and address. `look.ts` still owns the forty-four looks, their `?look=` grammar and every sentence they produce (Copy prompt, `llms.txt`'s Looks), unused by the UI, so they can come back; `lookAttributes` is what an element that sets its own theme spreads.
- Fun mode is off in the UI since plans/019 removed Customize; its code and these rules stay for when it returns. Fun mode's rule: it changes how things move, never how they look at rest. A component's fun path runs only when `useFun()` returns its motion, and the code that runs without it stays exactly as it was. Check it by screenshotting the affected pages with fun mode on, after they settle, against Calm: they must match to the pixel.
- The gallery itself does lead with fun mode when it is on, from each page's `meta.fun` (what to try there): a Fun group at the top of the sidebar and the phone menu, a Fun filter first on the overview, and that line under the page's title. These cues are gallery chrome, not components, and carry `data-fun-cue`: hide them (or leave the nav out) when you compare Calm and Fun. Give a page `meta.fun` when its component gets a fun path.
- `gallery/src/motion/rules.ts` mirrors the motion bounds in `check.mjs` (check 9) and the radius rule (check 7). Change them together.
- `tune` (`gallery/src/components/tune.tsx`) builds an Inspector from `useTune(name, (t) => ({ … }))` and checks corners, spaces and springs with `rules.ts`. Each `TuneRoot` owns a store by name: the first mounted component's fields drive the panel, and a control keeps only what differs from the code's defaults. Every litt token name it prints sits whole in a string, so the registry renames it, and no comment in it may name a custom property that is not a litt token (the registry's verifier reads comments too). `npm run test:rules --prefix gallery` (part of `verify`) fails when `SPACE_SCALE`, `RADIUS_PILL` or the corners `cornerRule` accepts drift from tokens.css. The gallery's stage and tile pass `enabled`, since the gallery is a production build; the smoke page leaves it off one root to prove the panels hide there.
- No hex values and no off-scale radii in `gallery/src`. `npm run lint:litt --prefix gallery` fails on both. The lint lives in the skill (`skills/litt-md/scripts/lint-litt.mjs`, so it ships with it); `gallery/scripts/lint-litt.mjs` only runs it. Its `--host` mode lints code in an app that installed the registry (the `litt-…` names), and `npm run test:lint --prefix gallery` (part of `verify`) self-tests both modes on `gallery/scripts/lint-fixtures/`.
- No class list in `gallery/src` puts two Tailwind utilities on one element that set the same properties under the same variant chain: both have the same specificity, so Tailwind's order picks the winner, not the order written (the Flat switch's `…:bg-fg` beat the `…:bg-accent` that `tone="accent"` joined on). `npm run lint:collisions --prefix gallery` (part of `verify`; `gallery/scripts/collisions.mjs`) reads every `className` with the TypeScript compiler (strings joined, ternaries, constants, Records, what a local function returns; never a class that arrives through a prop) and asks Tailwind what each class sets. Give each case its own string, a Record or a ternary. Collisions not yet fixed sit in its `KNOWN` list with the class that wins today and the number of places, which prints them and fails when one is gone, its winner changes or it is in more places. `npm run test:collisions --prefix gallery` (part of `verify`) puts the old switch pill back in `gallery/scripts/lint-fixtures/collisions-dirty.tsx` and fails if the check misses it.
- `skills/litt-md/scripts/litt-check.mjs` turns host mode into a score for any app (the skill's check mode, `workflows/check.md`). `npm run test:check --prefix gallery` (part of `verify`) self-tests it on the same fixtures. Change it with the lint when a host rule changes.
- `npm run test:agents --prefix gallery` is the agent test: Claude (`claude -p`, with this repo as the plugin) gets a fresh Vite or Next.js app and a task from `evals/agents/`, and the result is graded with litt's own checks (the skill loaded, registry components installed and composed, the host lint, typecheck, build, Chromium screenshots, and an optional screenshot judge). It costs money and takes minutes per task; `--fake-agent ../evals/agents/fake-agent.mjs` tests the harness for free. Run it when the build workflow, the registry or the host lint change. `evals/agents/README.md` has the details.
- The gallery is also litt.design's `/systems/` zone: litt.design rewrites `/systems/*` to this deploy's root. So the build is relative (`base: "./"` in `vite.config.ts`): load everything through `import.meta.env.BASE_URL` or a relative path, never a root `/…` path. A visit with no hash opens the page its path ends in (`route.ts`, and the preload script in `vite.config.ts`), so `/systems/` opens `#systems`.
- `vercel.json` is the deploy config: `npm ci`, then `verify` and `build`, output `gallery/dist`. `gallery/vercel.json` is the same config for a Vercel project whose Root Directory is `gallery` (what an import detects); the two differ only in paths, so change them together. A push to a branch makes a preview, and `main` is production.

## Content rules

- `skills/litt-md/assets/tokens.css` is the only place hex values live. Markdown names variables (`--accent`, `--surface-2`) and explains the reasoning.
- `taste/` is Nick's. Change it only through the protocol in `skills/litt-md/workflows/evolve.md`.
- Commit taste changes with a `taste:` prefix. Never push without asking.
- Refer to Nick by name or as "you". Never use gendered pronouns.

## Checks before committing

```
claude plugin validate .
node skills/litt-md/scripts/check.mjs        # every mechanical check (the list is in the script header)
npm ci --prefix gallery && npm run verify --prefix gallery && npm run build --prefix gallery   # when gallery/ or the tokens change
```
